# TICK 多人協作規則

> 適用於所有需要現場點名、派發、核對或確認的清單。新增任何 TICK 項目時，必須遵守本文件；不可自行設計另一套同步方式。

## 核心語義

每一行有兩個概念：

- **TICK**：正向動作，只代表「我現在核對到／確認到」。一般儲存只能 ADD，不能因為本機是空白而刪除後端已有的 TICK。
- **修正 TICK**：一次性的反向動作，只能在畫面同時為 `TICK=Y`、`修正=Y` 時執行，代表「取消這一次已存在的 TICK」。完成後兩格都回復空白。

禁止把「本機沒有 TICK」當成取消指令。

## 多人同時操作

假設 A 的本機只見到 1、2、3，B 的本機只見到 2、4：

```text
A：1、2、3
B：2、4
```

後端合併後必須是：

```text
1、2、3、4
```

重覆 TICK 是冪等操作，不會互相抵消。

A 之後儲存時，A 本機的 4 號空白不能把 B 已經 TICK 的 4 號清除。

## 修正規則

只有以下狀態才是取消：

```text
TICK=Y + 修正=Y
```

取消後：

```text
TICK=空白 + 修正=空白
```

之後若另一位工作人員真的再次核對到該項目，可重新 TICK；修正不是永久封鎖。

## 後端欄位建議

每個 TICK 工作表至少應有：

```text
item_id
checked_in / ticked
correction_action
updated_at
updated_by
updated_by_id
```

後端必須區分：

1. 普通 TICK（ADD）
2. 修正 TICK（REMOVE）
3. 本機沒有 TICK（NO-OP，不送出刪除）

如需處理離線／舊本機資料，應以操作時間或版本號拒絕舊操作，但不能用整份本機清單覆蓋後端。

## 統計

排序或篩選後的統計必須按目前顯示範圍計算，格式為：

```text
已到／回覆出席／該區或該支部 FULL LIST
```

例：

```text
SKW：11/11/15
小童軍：12/14/14
```

## 新增 TICK 功能檢查表

- [ ] 正常空白不會覆蓋別人已 TICK
- [ ] 多人 TICK 採用集合合併
- [ ] 修正必須同時有 TICK 及修正動作
- [ ] 修正完成後兩格清空
- [ ] 修正後可由另一人重新 TICK
- [ ] 後端保存最後操作者、時間及動作
- [ ] 排序／篩選後統計只計算目前範圍
- [ ] 多裝置重新載入後使用後端最新資料

目前典禮優異旅團點名已採用此規則。其他既有 TICK 模組（例如紀念章派發）在改動前，必須先補上獨立的修正動作欄及後端合併測試，不能只把普通 checkbox 複製過去。
