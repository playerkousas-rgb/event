# 👤 帳戶開設、密碼管理與權限授權

> 目的：兩種方式開戶（後端開戶表 + 前端開戶卡片），預設密碼 1234，登入後自行改密碼；並提供「權限管理」卡片，讓上級把「看/管」權限授權給下級。

## 一、開戶表（Account_Setup）

`initializeSheets()` 會自動生成一個名為 **`Account_Setup`** 的工作表，欄位如下（第 1 列為表頭）：

| 欄位 | 說明 |
|---|---|
| `name` | 名字（必填） |
| `role` | 職位層級（下拉選：主席／顧問／管理員／副主席／總主任／主任／工作人員） |
| `job_title` | 職稱（例：副主席（主題節目）） |
| `group_name` | 組別（例：主題節目組） |
| `user_id` | 帳號（可留空，系統自動產生 `staff_10001` 等，並回寫到本表） |
| `email` | 電郵（選填，登入時可當帳號用） |
| `contact` | 電話（選填） |

## 二、如何開戶

1. 在 Google Sheet 打開 `Account_Setup`，從第 2 行起逐行填寫。
2. 選單列「**童軍活動管理 → 開戶（同步 Account_Setup → Users）**」。
3. 完成後每個新帳戶：
   - 帳號 = `user_id`（或自動產生）
   - **預設密碼 = 1234**
   - 已存在的帳戶只更新名字/職銜/組別，**不會覆蓋其已修改的密碼**。

> 也可透過前端 POST `action: syncAccountsFromSetup`（含 api_key）觸發同步。

## 三、用戶自行改密碼

1. 用戶登入後，右上角會出現「**修改密碼**」按鈕。
2. 輸入舊密碼 → 新密碼（至少 4 字元）→ 確認，即更新。
3. 後端 `changePassword` 驗證舊密碼後，把新密碼雜湊寫入 `Users.password_hash`。

### 執行副主席（統管整個活動）
- 層級 70，介乎主席(80)與副主席(60)之間。
- 默認**全看＋全管**所有卡片（跨組），與管理層同級。
- 可跨組開戶、可授權給所有下級（跨組）。
- 具備副主席級（層級 ≥ 60）的所有批核權（膳食、物資、財務等）。

> 超管（`sheep`）帳密僅存於 `Code.gs` 後端，不在開戶表內。

## 五、前端開戶卡片（總主任以上）

- APP 內新增「**開戶**」卡片，總主任或以上可見。
- 只能為**自己組別**開戶（管理員/超管可跨組）。
- 角色下拉只顯示「層級 ≤ 自己」的角色。
- 預設密碼 1234，登入後可自行修改（右上「修改密碼」）。
- 後端 `createAccount` 會做輕量防呆（總主任以上、同組）。

## 六、權限管理卡片（看／管授權）

- APP 內新增「**權限管理**」卡片，總主任或以上可見。
- 每張內容卡片有兩種權限：**可看到（perm_see）** 與 **可編輯（perm_edit）**。
- 上級只能把「**自己有的**」權利授權給下級：
  - 只能授權給「同組、層級比自己低」的下級。
  - 授權卡片清單 = 自己「可看」的卡片子集；「可管」⊆「可看」。
- 例子：
  - 行政副主席（看管 ABCDE）→ 授行政總主任「看 ABC、管 AB」；行政總主任再往下，就只能授出 ABC 的看、AB 的管。
  - 運作總主任（看管 DE）→ 他之下就只有 DE 的權。
- 後端把授權存入 `Users.perm_see` / `Users.perm_edit`（JSON 陣列）；登入後生效。

### 權限判定規則
- 內容卡片：有 `perm_see` / `perm_edit` 時**以授權為準**（無則回退角色/組別預設；管理層 level ≥ 70 默認全看全管，含執行副主席）。
- 管理類卡片（開戶、權限、用戶批量、批核中心）仍按角色層級。

## 七、關於「管理權 vs 批核權」的框架分工

- **內容「可編輯」權**（perm_edit）：決定誰能改該卡片的內容（攤位、名單、預算等），由上級往下授權。
- **批核權**（借物資、批車位、膳食批核、財務批核等）：這是「管理權真正發生作用」的地方，**由超管手動指定誰有批核權**。例如：超管把「物資/車位批核權」交給協調副主席，再由協調副主席安排本組誰負責批核。
- 因此「權限卡片」的看/管授權，與「批核權」是兩層：
  1. 卡片層（perm_see / perm_edit）—— 框架化、上級自助授權；
  2. 批核層 —— 超管手動指定，或批核權限人自行組內指派。

## 八、批核權限表（Approval_Permissions）＋ 前端批核頁兩種檢視

### 後端「批核權限表」
- `initializeSheets()` 會生成 **`Approval_Permissions`** 工作表，欄位：
  `user_id, name, group_name, supplies, vehicle, meals, finance`
- 4 個批核範疇：
  - `supplies` = 物資批核
  - `vehicle` = 車位/車輛批核
  - `meals` = 膳食批核
  - `finance` = 財務批核
- 有權的欄位填「**Y**」或「是」，無權留空。
- 管理層（主席/顧問/管理員/**執行副主席**/超管）預設全範疇，**不需列明**。
- 修改後，前端「批核」分頁點「重新整理」即生效（或重新開啟 APP）。

### 前端分頁（兩個獨立分頁）
1. **「批核」分頁**：
   - 上半部「**待你批核**」：顯示待批項目（物資／車位／財務），按 `canApproveArea` 判斷是否有權批准/拒絕；只有有權的範疇才顯示「批准/拒絕」按鈕，否則顯示「你無批核權」。
   - 下半部「**我的申請**」：申請人（每位登入者）查看自己的狀態——訂餐（吃什麼飯）、物資（借了什麼）、車位（有沒有位）、開支；每項用顏色＋文字標示 **待批／已批／已批(修改)／已拒絕**。
2. **「批核權限表」分頁**：檢視「誰有哪個範疇的批核權」，有兩種檢視：
   - **橫看（人 → 頁）**：表格每一行＝一位批核人，每一欄＝一個批核範疇，用**顏色晶片＋「有權/無權」文字**顯示。
   - **直看（頁 → 人）**：每個批核範疇一列，列出「有權」的批核人名單（同樣顏色＋文字分類）。

### 批核權判定（canApproveArea）
1. 管理層 → 全範疇。
2. `Approval_Permissions` 有該 user 的紀錄 → 以表為準。
3. 無紀錄 → 回退角色預設（協調/行政副主席→物資+車位；膳食/協調→膳食；層級≥60→財務）。

> 超管（你）隨時可在後端／用戶管理直接改任何人的權限，框架只是為了「減少手動」。
