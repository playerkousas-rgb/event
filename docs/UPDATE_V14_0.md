> 用戶要求（原文摘要）：「幫我先把位置及格式預留，同時預備可讓用戶上傳名單（EXCEL）或 WORD 或 PDF」；

## 2. 四張名單的「格式」（預定欄位；Excel／Word 匯入即照此對位）

欄位定義集中喺 `js/00-config.js` 的 `ROSTER_LIST_DEFS`（`columns`＝欄位、`match_fields`＝點名配對欄、`aliases`＝匯入時認嘅表頭）。**所有名單的最後一欄永遠係「TICK（點名）」＋「點名紀錄」。**

### ① 支部獎勵獲獎名單（`section_award`）— 頒發「支部最高獎章嘉許信」
| 欄位 | 說明 | 匯入時接受嘅表頭 |
|---|---|---|
| 區會 | 可選 CHW／HKN／HKS／HKW／SKW／VIC／WCH | 區會／area／District |
| 支部 | 小童軍／幼童軍／童軍／深資童軍／樂行童軍 | 支部／section／組別 |
| 旅團／單位 | 旅號或單位名 | 旅團／旅號／單位／unit |
| **獲獎人姓名**（必填） | 獲獎童軍姓名 | 姓名／獲獎人／name |
| 獎項（支部最高獎章） | 預設：總領袖獎章／榮譽童軍獎章／貝登堡獎章（可自填） | 獎項／獎章／award |
| 嘉許信／證書編號 | 大會編配編號（可後補） | 嘉許信編號／證書編號／編號 |
| 備註 | 代領、缺席安排等 | 備註／note |
| **點名** | TICK＝已點名／已上台 | — |
點名配對欄（`match_fields`）＝區會＋旅團＋姓名＋獎項。

### ③ 參加旅團名單（`participants`）— 行政組維護
| 欄位 | 說明 |
|---|---|
| 區會 / 旅團 / 支部 / **人數** / 領隊／旅長 / 備註 | v14 起範本加入「區會」「領隊」兩欄（舊檔只寫 旅團/支部/人數/備註 照樣讀到） |
| **報到**（TICK） | 旅團報到處逐團 TICK |

**點名對位 key（`match_fields`）**：支部獎勵＝姓名＋獎項；領袖獎勵＝姓名＋獎項＋所屬單位；參加旅團＝旅團＋支部；代訂餐盒＝旅團。
即係：之後先補「區會」欄、或改人數／備註再重新上載，**已做嘅 TICK 唔會因為多咗一欄而失效**（同一行對返同一個 TICK）。
* 名單本體仍以 `participants`（Drive 結構表 `participants_source` 或上傳 Excel）為準；**點名狀態另行儲存**，重覆匯入唔會弄丟已 TICK 嘅行。
* TOTAL 列自動加總人數。

## 3. 上傳名單：EXCEL／WORD／PDF（同一個入口）

每張名單嘅工具列都有：

| 按鈕 | 行為 |
|---|---|
| **上傳名單（EXCEL／WORD／PDF）** | `.xlsx/.xls/.xlsm/.csv` → SheetJS 讀第一張表，按表頭（中／英文 aliases）對位；`.docx/.doc` → mammoth：**優先讀 Word 內嘅表格**（`<table>`），冇表格時按「換行＋Tab／多空白／逗號」拆行；`.pdf` → 無法可靠解析行列，會**自動改做附件內嵌預覽**並提示用 EXCEL／WORD 或「貼上文字」。 |
| **貼上文字（由 PDF／網頁複製）** | 喺 PDF／網頁選取名單（連表頭嗰行）複製 → 貼入 → 即時生成行列（每行用 Tab／兩格以上空白／`,` 分隔）。呢個係只有 PDF 檔時最快嘅做法。 |
| 匯入預覽 | 一定先彈預覽：顯示解析到幾多行／首 60 行、揀「**取代**」或「**附加**」；內容欄位相同嘅行會保留原有 TICK。 |
| **上傳附件（PDF／Word／圖片／Drive 連結）** | 使用執行手冊附件上傳機制：Word 解析成文字內嵌、PDF 整份內嵌、圖片直接睇、可貼 Drive 連結；有版本欄、可下載／刪除。 |
| 下載格式範本 CSV | 按「預定格式」產生表頭＋兩行樣板，用家照樣板填好回覆上即成。 |
| 匯出 CSV／列印點名表 | 匯出連 TICK 狀態、點名時間、點名人；列印用既有 `printCoordArea`（A4 表格）。 |
| 同步名單至後端／由後端取回 | 已設 GAS 連線時可用（行內容＋TICK 狀態一次過推；取回時 upsert，唔覆蓋本地較新嘅 TICK）。 |

## 4. 點名（防錯與更正保護）

* TICK 勾選即時儲存；**取消 TICK 必須輸入更正原因**（無填就彈返原狀），原因會顯示喺「點名紀錄」欄並寫入後端 `correction_cancelled=Y`。
* 進度列：`已點名／總數`；分組 chips（支部獎勵＝按支部、領袖獎勵＝按獎項、參加旅團＝按支部、代訂餐盒＝按區會），每組顯示 `d/n`，全部 TICK 完可以做「**確認**」（寫入 `Roster_Rollcall_Batches`，顯示 ✅已確認）。
* 排序：按區會／支部／旅團／姓名（或該名單嘅欄位）＋「未點名優先」＋順序／倒序（↕）。
* 「全選本欄點名」：一次過 TICK 目前篩選結果（用於大批派發），仍需確認。
* 後端：每筆 TICK 寫 `Roster_Rollcall_Checkins`；GAS 端有「**只接受較新操作**」防護，避免舊裝置把新更正覆寫。

## 5. 權限（誰可改、誰可點名）

| 動作 | 誰可以 |
|---|---|
| 檢視名單 | **所有人（公開，無需登入）** |
| 上傳／編輯／刪除名單、上載附件、後端同步 | 管理層（super_admin／admin）、副主席以上（level ≥ 60）、**該名單負責組別內主任以上（level ≥ 30）**；行政組依 v8.14 慣例可統管全站名單 |
| 點名 TICK | 上述人士 ＋ **該負責組別任何已登入成員**（現場由本組工作人員逐個 TICK）；未登入／冇關組別只能睇 |
| 參加旅團名單嘅「名單本身」 | 仍由行政組經 Drive 同步或 Excel 上載（`handleParticipantsExcelUpload`／`handleParticipantsUploadFile`）；點名入口喺同一頁 |

判定函數：`rosterCanManage(key)`／`rosterCanTick(key)`（`js/41-roster-lists.js`）。附件區權限（`roster_<key>`）由 `canManageExecManualUpload()` 交返比同一個判定，唔會另外開一套。

## 7. 現況／下一步（版位已預留、內容待上載）

* 四張名單而家都係**空版位**（真實活動 `isd_2026`）：面板會顯示「版位已預留、內容待上載」提示，唔會有假資料混入。
* 待各組提供 2026 正式名單後：
  1. 支部獎勵／領袖獎勵：向地域秘書處／各區會索取「最高獎章嘉許信」及「領袖及委員獎勵」名單（Excel 最好；只有 PDF 就用「貼上文字」）；
  2. 參加旅團名單：行政組提供 Google Sheet ID 填入 `data/isd_2026.json` 的 `participants_source.sheet_id`（即可每次開啟自動同步），或直接上載 Excel；
  3. 代訂餐盒：協調組用判單 Excel 上載，之後每日核「對數」行。
* 之後可考慮（未做）：名单行级编辑权限再细分（例如只俾典礼组总主任改奖项）、同「紀念章派發」一樣嘅手動「💾 儲存」批次模式、以及把四張名單併入「我的監察」進度卡。
