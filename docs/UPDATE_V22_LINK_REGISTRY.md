## 點解要做連結總表

實測 `data/mock_demo.json`：

```
74 條獨立連結，散落喺 121 個位置
```

最誇張嗰兩條：

| 出現次數 | 連結 |
|---:|---|

| **13 處** | 特別通告第 12/26 號 PDF（通告庫／公告／旅團指南／各支部須知…） |

換一次檔要手改十幾處。**必然會漏一兩處**，然後就「對唔上」——
呢個正正就係「冇框 → 改到對唔上 → 自動更新失效 → 要人手夾」嘅起點。

## 點樣做

```
一條連結  =  一個 id ＋ 一個主人 ＋ 一個 URL ＋ targets[]（用喺邊幾個位）

          後台改一次 URL
                 ↓
   開頁 loadEventData() → applyLinkRegistry()
                 ↓
        自動寫返入全部 targets
                 ↓
   通告庫 · 公告 · 旅團指南 · 會議 · 公眾頁 … 一齊變
```

### 登記處點嚟

`tools/build_link_registry.js` **機械掃**出嚟，唔靠人填：

- 掃全份 `mock_demo.json`，淨係收「整條字串就係一個 URL」嘅欄位
- 同一條 URL 歸一筆，所有出現位置入 `targets[]`
- **類型**由副檔名／網域推（📁 資料夾 · 📊 EXCEL · 📝 WORD · 📋 表單 · 🗺️ 地圖 · 📄 PDF · 🌐 網頁）
- **負責組**三層推導：① 資料本身嘅 `uploaded_by`／`owner_group` → ② `category` 對照表 → ③ 路徑規則
  結果分佈合理：秘書處 31 · 行政組 13 · 主題節目組 11 · 嘉賓接待組 6 · 會操及典禮組 6 · 協調組 5 · 服務及發展組 1 · 品牌推廣組 1
- **夾喺內文中間**嘅連結（3 處）唔自動換，但會**着燈**叫人手跟——唔會靜靜雞做錯嘢

```bash
node tools/build_link_registry.js --dry   # 只睇唔寫
node tools/build_link_registry.js         # 寫入 data/mock_demo.json 嘅 link_registry
```

### 介面：部門中心 → 🔗 連結總表

- 一般組只見到**本組負責**嗰幾條；秘書處／行政組／管理層見全部
- 每條顯示：類型・負責組・**用喺 N 個位**（可展開睇晒邊幾個位，中英對照）

呢個計分板就係明年嘅**工作清單**：48 條着住「仲係 2026 版」嘅燈，熄一條得一條。
