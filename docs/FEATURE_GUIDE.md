## 1. 系統是什麼

本系統是一個「大型活動行政管理工具」，結合：

- **Google Sheet + Google Apps Script (GAS)** 作為後端，集中管理活動資料。
- **前端網頁 (HTML + 內建 JSON)** 作統一入口，可在手機及電腦使用。
- **多活動接入**：可同時管理港島童軍繽紛日、港島毅行、其他大型活動及演練用示範版。
- **公開查閱**：大部分資料（日程、場地、聯絡、通告、儀式、申請表入口等）無需登入即可閱讀。
- **身份登入**：修改資料、提交申請、批核、統計、開戶等需要依職級／組別登入。

## 2. 現有功能：三類卡片

進入活動後，儀表板會根據身分顯示不同數量的卡片。

| 身分 | 顯示內容（順序） | 顏色 |
|---|---|---|
| **未登入**（一般工作人員／公眾） | 公開資料：**公告及溝通 → 執行手冊（內含組織架構・場地・典禮・危機・通告）→ 申請中心 → 童心捐贈大行動**（統計不公開）＋「登入後解鎖」卡片 | 只有**公告及溝通**及**申請中心**有顏色，其餘一律無顏色（白底），方便一眼找重點 |
| **登入（任何職級）** | **公開資料 → 其他組別及工作卡片（會議卡片最前，自己組標亮）→ 管理工具（總主任以上）**；**我的監察**已併入頂部活動橫幅（日期/時間/地點/天氣＋活動簡介＋最新消息同一橫幅） | 維持原有設計 |
| **登入（L3 或以下：副主席／總主任／主任／工作人員）** | 同上（公開資料 → 其他組別及工作卡片）；我的監察已併入頂部活動橫幅，沒有批核權限人士只看到自己身份＋未有申請紀錄提示，可到「申請中心」提交 | — |

> 簡單記法：**唔登入淨係兩張彩色（公告、申請中心）；排序＝公開資料 → 其他組別及工作卡片（會議卡片最前）→ 管理工具；我的監察併入頂部活動橫幅。**

### 首頁活動類別

首頁把活動分為四類：

- **港島童軍繽紛日**：步操檢閱、頒獎典禮與攤位博覽。
- **港島毅行**：步行籌款活動。
- **其他大型活動**：大型露營、培訓及活動。
- **模擬示範版**：完整示範假資料，本地沙盒，改動不會影響正式活動。

### 3.4 申請表及導航規則（v8.6）

- **物資申請一次可申請多項**：每項物資只填「物資名稱＋數量（＋單位）」；**所屬組別、聯絡電話、申請原因屬整張申請，只填一次**。聯絡電話自動載入你登記時嘅號碼，借十樣嘢唔使填十次電話。提交後每一項仍係獨立一條紀錄，逐項批核／修改數量。
- **攤位物資申請＝獨立卡片**：枱／椅／帳篷圍布／電源等向外判商租用嘅項目，對標「2026 攤位總表」（分區＋編號＋負責單位由表選擇、攤位招牌名稱自填、標準項目只填數量、另有運送／其他需求）。同地域物資借用**完全分開**——唔再掛喺物資申請卡嘅頁籤／統計入面。
- **菜單不設「組別」欄**：膳食菜單開放俾所有組別填寫訂餐；邊個訂咗邊組飯，以每張訂餐單上嘅「組別／攤位」為準。
- **返回＝上一層級**：全部頁面頂部只有一個「← 返回」掣，一律返回上一頁（由申請中心入咗子表，返回就返申請中心；唔會多一個「返回申請中心」重複掣）。批核中心／批核權限表／用戶管理／批量開戶／控制台亦已補上同款返回。
- **公眾（未登入）可見範圍**：膳食只有「菜單＋我的訂餐」——訂餐紀錄/統計與列印派發只供本組總主任以上／批核組／執行組；攤位物資申請**公開可填寫（無需登入）**，未登入須留姓名＋聯絡電話，清單上申請人聯絡資料對公眾隱藏；童心捐贈對公眾直接顯示兩張捐贈表（冇多餘「捐贈登記」頁籤；QR Code／下載只列予籌辦方）；物資（地域借用）、車輛／泊車證、開支申報仍需登入。
- **部門卡數字口徑**：主頁「部門管理中心」卡片嘅「N 崗位 · M 人」與進入卡片後嘅崗位數，同一份計算（只按組織架構圖，顧問團＝2 人），兩處必定一致。**v8.9 起**去重改用「正規化 key」（忽略換行／全形空格／半全形括號／人名分隔符差異），Drive 同步、上傳 JSON/CSV 與本機快取三邊都唔會再令崗位、人數或職務大綱內容變成 ×2；發現髒快取會自動校正寫回。

## 4. 各職級權限及權限制度

### 4.1 職級與預設權限總表

| 層級 | 職級 | 代碼 | 預設權限 | 用戶管理可視範圍 |
|---|---|---|---|---|
| L1 | 管理員 | admin | 全部可看、全部可管（行政／秘書處常用） | 可見全部人 |
| L1 | 顧問 | advisor | 全部可看、全部可管（顧問團） | 可見全部人 |
| L1 | 主席 | chairperson | 全部可看、全部可管 | 可見全部人 |
| L2 | 執行副主席 | executive_vice_chairperson | 大部分可看可管（高層統籌） | 可見全部人 |
| L3 | 副主席 | vice_chairperson | 可更新日程／主題章／儀式／危機等；管理本組 | 只睇自己組全部成員 |
| L4 | 總主任 | general_director | 可管理本組、申請、批核、開戶、報價 | 自己組，不包括副主席及以上 |
| L5 | 主任 | director | 可管理本組內容、上傳活動、申請 | 自己組普通工作人員 |
| L6 | 工作人員 | staff | 可登入、提交申請、查看自己組 | 原則上無權管理用戶 |
| L7 | 公開 | public | 只可看公開資料（無需登入） | — |

> 註：以上為「預設」權限。系統支援上級透過「權限管理」把更細的「可看／可管」授權給下級（`perm_see`／`perm_edit`）。

### 4.2 權限制度運作方式

1. **卡片可見度（minLevel / groups）**
   - `minLevel = 0`：公開，所有人可見。
   - `minLevel > 0`：需登入且職級達標，或屬於卡片指定組別。
2. **卡片修改權（editLevel / editGroups）**
   - 達到 `editLevel` 或屬於 `editGroups` 才會顯示「可修改」；否則顯示「只讀」。
   - 各模組另有實作權限（如訂餐、物資、財務、上傳），會以卡片內按鈕及提示為準。
3. **角色授權（perm_see / perm_edit）**
   - 若上級已為某用戶設定權限清單，系統會以該清單為準。
   - 管理層（管理員／顧問／主席／執行副主席）預設全看全管。
4. **組別卡片**
   - 登入後仍可只讀查閱其他組別卡片，方便跨組協作。
   - **所有登入職級**：自己的組別併入「其他組別及工作卡片」並標亮（會議卡片在功能卡片最前）；我的監察已併入頂部活動橫幅。
5. **用戶可見範圍**
   - 管理員／執副／主席／顧問＝可見全部人。
   - 副主席＝只睇自己組。
   - 總主任＝自己組，不包括副主席及以上。
   - 主任＝自己組普通工作人員。

### 4.3 開戶權限

- 前端開戶卡片只提供：**工作人員／主任／總主任** 三級。
- **副主席／執行副主席／主席／顧問**：由管理員另行處理。
- **管理者（管理員）帳戶**：可由管理員另開（如秘書處）。
- 籌委會架構 54 人已全部預先開戶（見 `data/committee_accounts.csv`），冇資料嘅可於「用戶管理／開戶表／批量 CSV」補。
- 工作人員（數量多、名單後補）由各組自行開戶。
- 組別下拉（開戶／登記）不包含「顧問團」及「主席及執行副主席」兩組。

### 4.4 申請批核路由（重要）

「批核路由」＝每一類申請（物資、車位／泊車證、膳食、財務開支）都有一條流程，而**「誰批核」和「批准後誰跟進」都是由管理層指定、可隨時更改的**。每一類申請都要指定兩個組別（**均可多選**）：

| 組別 | 負責什麼 | 簡單例子（膳食） |
|---|---|---|
| **批核組** | 決定「批／唔批」；可修改批准數量／金額，也可拒絕 | 由**行政組**決定批唔批 |
| **執行／最後名單組** | 批准之後負責跟進，並持有最終名單：落單、派發、列印入口檢查清單（如泊車證） | 由**協調組**按名單落單及派飯 |

- 設定方法：**管理員／顧問／主席／執行副主席**在「批核權限表」以多選按鈕揀組別 → 按「確定更新批核表」即生效。預設如下：

| 申請範疇 | 預設批核組 | 預設執行／最後名單組 |
|---|---|---|
| 物資申請 | 協調組 | 協調組 |
| 車位／車輛（含泊車證） | 協調組 | 協調組 |
| 膳食申請 | 行政組 | 協調組 |
| 財務申請／開支 | 行政組 | 行政組 |

**實際流程（以「會操及典禮組」的主任申請物資為例）：**

1. **提交**：主任／工作人員在申請中心提交申請。
2. **本組總主任確認**：因為批核組未必熟悉申請人所屬的組別，申請會先由**申請人所屬組的總主任或以上**確認（代表「本組確認這張申請屬實、確實需要」），在「批核中心」會看到「本組確認」按鈕。**若申請人本身已是總主任或以上，此步自動跳過。**
3. **指定批核組批核**：本組確認後，申請才會交到「批核權限表」目前指定的**批核組**做最終批准／拒絕／修改。
4. **指定執行組跟進**：批准後，只有目前指定的**執行／最後名單組**（及管理層）可查看最後名單、列印入口檢查清單（例如泊車證），其他組別看不到。

- 「人員權限表」可在已指派的批核組內再收窄至指定總主任；沒有個別紀錄時，該批核組的總主任以上均可處理；管理層保留監察及代批權。
- 會操及典禮組不會在未被明確指派時自動取得物資批核權。

## 5. 可延展的功能

本系統已預留以下擴充方向，供日後發展：

1. **多活動接入**：切換不同年度／類別的活動，甚至擴展到其他地域活動。
2. **通用化**：將童軍專屬內容（警察學院、步操檢閱等）參數化，變成「活動類型可配置」，供其他大型活動重用。
3. **動態批核路由**：已可多選「批核組／執行組」，未來可再加入條件式路由（按銀碼、組別、日期等）。
4. **權限授權**：已支援 `perm_see / perm_edit` 授權，未來可做到「每一張卡片、每一個動作」皆可細粒度授權。
5. **統計儀表板**：現有各組訂餐統計、物資統計、財務統計，可擴充為跨活動匯總、圖表及匯出。
6. **文件／Drive 整合**：會議 Drive 即時連通、文件上傳至指定資料夾，可擴充為「自動同步、版本記錄、全文檢索」。
7. **CSV／批量作業**：已有批量開戶、批量上傳，可擴充為批量匯入人員、物資、財務、攤位、日程。
8. **全域搜尋**：現有全域搜尋可擴充為跨卡片全文檢索（包括文件內容、申請紀錄）。
9. **捐贈管理**：已預留 QR Code 登記及統計總表。
10. **離線／快取**：資料以 `localStorage` 快取，可擴充為更完善的離線同步。
11. **後端結構自動更新**：GAS 使用 `ensureSheet` 智慧結構檢驗，新增功能時只補齊缺失欄位，不會覆蓋舊資料，方便持續升級。

## 6. 其他用戶需要了解的地方

### 6.1 公開查閱 vs 登入修改
- **無需登入**即可查看「公開資料」卡片。
- **修改資料、提交申請、批核、開戶**必須登入。
- 登入狀態會保存在瀏覽器 `localStorage`，**一次登入永久有效**，直到主動登出。

### 6.2 如何登入／開戶
- 帳號＝**中文姓名**（例如「朱家聰」）。
- 初始密碼：**1234**（首次登入後建議立即改密碼）。
- 如需要開戶，請找**所屬組別的總主任**；管理層帳戶由管理員處理。

### 6.4 資料來源及同步
- 正式活動：資料可保存在 Google Sheet（GAS 後端），會實時同步。
- 內建資料：部分內容（活動、會議紀錄、組織架構等）來自 `data/*.json`，隨 APP 一齊發佈。
- 管理員可於「系統設定 / GAS URL」設定後端網址；未設定時整站以本地資料運行。
- 會議卡片讀取公開 Drive 資料夾，檔案需設為「知道連結的任何人可查看」。

### 6.5 私隱與安全
- 公開資料刻意公開（讓任何人快速了解活動）；聯絡電話／Email 需登入才可查看／匯出。
- 活動密碼、登入密碼會儲存於瀏覽器；敏感帳密不會在網頁源碼顯示。
- 「用戶管理／權限管理」及「批核權限表」只開放給有權限的職級。

### 6.6 手機使用
- APP 已針對手機優化；手機底部有「首頁／會議／成員／開戶」快捷列。
- 表格在手機上會以「標籤＋值」方式顯示，方便閱讀。

### 6.7 遇到問題
- 睇唔到卡片：可能是卡片屬登入後模組，或你的職級／組別未達標，或該活動未有資料。
- 要改資料冇按鈕：代表你的權限只有「只讀」，請向該卡片的可修改職級／上級反映。
- 資料未更新：會議 Drive 檔案請重新入卡片或按「讀取最新」；其他資料可重新載入頁面。

## 7. 快速問題 (FAQ)

**Q：不登入可以看到什麼？**
A：公告及溝通、執行手冊（組織架構・場地與活動總覽・典禮儀式・危機處理・通告及文件，內部分頁）、申請中心、童心捐贈大行動（只可填表／掃碼，統計不公開），全部只讀。

**Q：登入後有咩唔同？**
A：**排序＝公開資料 → 其他組別及工作卡片（會議卡片最前，自己組標亮）→ 管理工具（總主任以上）**。**我的監察**已併入頂部活動橫幅：沒有批核權限人士只看到自己身份＋「你暫時未有申請紀錄，可到申請中心提交」；有權限人士另見總申請／待處理／已批核／已拒絕，點擊數字可跳轉批核中心查看內容並處理。**未登入**：得「公告及溝通、申請中心」兩張彩色，其餘無顏色，方便搵重點。

**Q：點解我冇得修改某張卡？**
A：表示你冇該卡的修改權限（只讀）。可睇該卡顯示的「可修改：誰」提示，或向該卡負責人／上級查詢。

**Q：我可以幫下屬開戶嗎？**
A：總主任以上可為本組開「工作人員／主任／總主任」；批量開戶由管理員使用。

**Q：申請咗膳食／物資／泊車證，點知批咗未？**
A：登入後用「我的監察」，一頁看齊自己＋下級的申請進度；亦可在申請中心／卡片上看狀態及通知。

**Q：物資申請點解要逐項填組別／電話？（舊版問題）**
A：已解決（v8.6）。每項物資只填「名稱＋數量」；所屬組別、聯絡電話同申請原因係整張申請共用欄，只填一次，電話自動載入你登記時嘅聯絡號碼——借十樣嘢唔使填十次。

**Q：點解「物資申請」入面冇咗「攤位物資」頁籤？**
A：改咗做**獨立卡片**「攤位物資申請」（申請中心都有入口）。地域物資借用同攤位物資（向外判商租用）係兩項完全獨立嘅紀錄，UI／統計／列表都唔會再混埋。

**Q：主頁部門卡／部門中心「崗位數、人數、職務大綱」点解會翻倍？**
A：有兩個來源會重複計同一崗位：① 瀏覽器快取與內置 JSON 合併；② Drive 架構圖同步或「上傳 JSON/CSV」把同一崗位再寫一次。v8.6 已按「組別＋職位＋人名」去重，但 v8.9 前嘅 key 係用**原文**比較——只要 Drive 檔嘅職位格有換行、括號係半形、或人名用「、」以外嘅分隔符，就對唔返，於是又變 ×2（連點入部門中心嘅職務大綱都會重覆）。
**v8.9 修法**：① 去重 key 一律先正規化（去換行／空格、統一半全形括號、人名拆任何分隔符後排序）；② 本機改動／同步改做「同 key 覆蓋」（upsert）而唔係追加，並用穩定 id；③ `job_duties`／`contacts` 同時去重；④ 開 APP 發現髒快取會自動校正寫回；⑤ `data_version` 上調令舊快取一次性清除。詳情見 `docs/UPDATE_V8_9.md`，回歸測試 `tests/v89_org_chart_duplication_test.js`（69 項）。

**Q：菜單入面嘅「組別」欄去咗邊？**
A：查證後發現嗰欄只係展示用途，唔影響任何篩選／統計／訂餐流程（邊組訂咗飯以每張訂餐單嘅「組別／攤位」為準），屬無效欄位，已喺 v8.6 刪除。

**Q：點返去上一層？我入錯卡點算？**
A：所有頁面頂部得一個「← 返回」，一律＝返回上一層級（申請中心→子表→返回＝返申請中心）。各卡片已冇第二個「返回申請中心」重複掣；撳多一次返回先返主頁。

**Q：呢個系統係咪只係「2026 港島童軍繽紛日」用？**
A：唔係。系統支援多活動接入，內建分類包括港島童軍繽紛日、港島毅行、其他大型活動，亦容許新增活動。
