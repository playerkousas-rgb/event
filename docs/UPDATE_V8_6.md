# v8.6 更新（2026-08-28）

本輪按用戶回報修正五項：

1. **主頁／部門卡「崗位數 ×2」修復**
   - 成因：`getStaffData()` 以 JSON 為底再併入本機 `localStorage`（全部帶 `_userEdited`）；JSON 種子崗位冇穩定 id，merge 永不命中 → 舊快取整份被追加，同一崗位出現兩份。主頁／部門卡以「職位|人名|level 字串」去重，舊快取 level 編號格式不同 → 去重失效 → 崗位數翻倍（人數按姓名去重所以冇事，先出現「只有崗位 ×2」嘅怪象）。
   - 修法：①種子崗位改用穩定 id `org_seed_i`，本機編輯按 id 對回；②`getStaffData()` 按「組別|職位|人名」去重（保留資料較齊／經本機編輯嘅一份）；③`getGroupOrgNodes()` 去重 key 唔再計 level 字串；④`data/isd_2026.json` data_version 上調至 `2026-08-28T00:00:00Z-v6`，自動清走全站舊 staff/crisis 快取（v8.2 機制）。
   - 顧問團繼續以架構圖兩行（黃偉安／何家騏）計算＝2 人，唔再併計舊聯絡表。

2. **物資申請表簡化（一次申請多項）**
   - 每項物資只填「物資名稱＋數量（＋單位）」；**所屬組別／聯絡電話／申請原因係整張申請共用，只填一次**。
   - 聯絡電話自動載入申請人登記電話（帳戶 contact／聯絡表），唔使借十樣嘢填十次。
   - 一般成員（總主任以下）所屬組別自動填入本組（唯讀）；管理層／總主任以上可代其他組別填寫。
   - 資料結構不變：後端 Supply_Requests 每項一條紀錄，共用欄位逐條寫入，批核流程冇影響。

3. **攤位物資申請＝獨立模組（同物資申請徹底分開）**
   - `openModule('booth')` 由「借道物資申請卡＋彈表單」改為獨立 `renderBoothModule()`：自己嘅說明、統計（申請／待批／已批）、提交按鈕、清單同匯出。
   - 物資申請卡刪除「攤位物資」頁籤、頂欄「攤位物資申請」按鈕、統計內「攤位物資統計」；兩項紀錄除同一後端儲存檔外喺 UI／流程完全不混雜。

4. **菜單「組別」欄刪除**
   - 舊菜單表單嘅「組別 (空=全部)」只係喺菜單卡展示，**唔影響任何篩選／統計／訂餐流程**（訂餐本身已逐單填組別）。屬無效欄位，已由表單及菜單卡刪除；舊資料讀取保持相容。

5. **返回按鈕統一（所有卡片排查）**
   - 刪除物資申請／膳食／泊車證三張卡重覆嘅「← 返回申請中心」按鈕；「返回」統一用模組頁頂部掣＝**返回上一層級**（申請中心入去 → 返申請中心；主頁入去 → 返主頁）。
   - 補齊原本冇返回掣嘅全頁：**批核中心／批核權限表／用戶管理／批量開戶／控制台**加同一個「返回」。
   - `backToDashboard()` 加防呆：無歷史且無選活動時回「選擇活動」頁，唔會出錯。

測試：新增 `tests/v86_forms_back_nav_test.js`（47 項，含舊快取翻倍場景、兩卡互不混雜、表單欄位、返回導航）；全部 v8.2–v8.6 測試綠。

## 跟進：公眾（未登入）視角修正

用戶以未登入帳號實測後三項修正：

1. **膳食**：未登入／一般成員不再見到「訂餐紀錄/統計」與「列印派發」頁籤——兩頁籤只對本組總主任以上、批核組、執行組及路由管理員開放；公眾保留「菜單（可即場訂餐）＋我的訂餐（本裝置紀錄）」。`mealsSubTab` 對無權限者自動夾返「菜單」。
2. **童心捐贈**：刪除公眾頁入面多餘的「捐贈登記」單頁籤 icon（內容本身已是登記頁，單一頁籤屬重複）；QR Code＋下載欄屬籌辦方派發用途，只對服務及發展組／管理層顯示。
3. **攤位物資申請＝公開可填寫**：任何人（無需登入）都由「申請中心→攤位物資申請」直接入表填寫；未登入必須留「提交人姓名＋聯絡電話」，所屬組別／單位自填（登入者則自動鎖本組）。公眾睇清單時申請人／聯絡資料隱藏（私隱），批核狀態照常可見；提交後照常進入「本組總主任確認→指定批核組」流程。同場確認：物資申請卡嘅「全部清單／待批核／物資Check List／統計／通知」管理頁籤本来就只供批核／執行／管理組，一般人員只見到「我的申請」。

另修正 `renderBoothModule` 匯出/提交按鈕在公開狀態嘅標籤（公眾見「提交攤位物資申請（無需登入）」）。

測試：`tests/v86_forms_back_nav_test.js` 加 ⑥ 公眾視角段（源碼斷言＋未登入 vm 真渲染＋匿名提交攤位申請全流程，合共 75 項）；9 檔測試全綠。
